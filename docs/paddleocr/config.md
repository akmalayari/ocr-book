# PaddleOCR-VL — Configuration and Parameters

## Reference YAML Config

File: `paddlex/configs/pipelines/PaddleOCR-VL-1.5.yaml`

```yaml
use_doc_preprocessor: False      # orientation + unwarping disabled
use_layout_detection: True
use_chart_recognition: False     # charts treated as images
use_seal_recognition: False
format_block_content: False      # extra formatting in .json() disabled
merge_layout_blocks: True
markdown_ignore_labels:
  - number       # page numbers
  - footnote
  - header
  - header_image
  - footer
  - footer_image
  - aside_text

SubModules:
  LayoutDetection:
    model_name: PP-DocLayoutV3
    threshold: 0.3
    layout_nms: True
  VLRecognition:
    model_name: PaddleOCR-VL-1.5-0.9B
    genai_config:
      backend: native             # replaced by llama-cpp-server in our config
```

## `PaddleOCRVL(...)` Constructor Parameters

| Parameter | Default | Description |
|---|---|---|
| `vl_rec_backend` | `"native"` | VLM backend. Values: `native`, `llama-cpp-server`, `vllm-server`, `sglang-server`, `mlx-vlm-server`, `fastdeploy-server` |
| `vl_rec_server_url` | — | Server URL (ex: `http://127.0.0.1:8080/v1`) |
| `vl_rec_api_model_name` | — | Model name for the server (ex: `"paddleocr"`) |
| `use_layout_detection` | `True` | Layout detection. `False` = simple fallback, degraded quality |
| `use_chart_recognition` | `False` | Specialized chart recognition |
| `use_doc_orientation_classify` | `False` | Rotation correction (requires additional model) |
| `use_doc_unwarping` | `False` | Page curvature correction |
| `format_block_content` | `False` | HTML block formatting in `.json()` |
| `merge_layout_blocks` | `True` | Merge adjacent blocks of same type |
| `markdown_ignore_labels` | see YAML | Block labels ignored in markdown output |

## `predict()` / `predict_iter()` Parameters

| Parameter | Default | Description |
|---|---|---|
| `max_new_tokens` | — | Max tokens generated by the VLM |
| `temperature` | — | Sampling temperature |
| `top_p` | — | Top-p sampling |
| `repetition_penalty` | — | Repetition penalty |
| `min_pixels` | — | Min pixels for vision encoder (not supported with `llama-cpp-server`) |
| `max_pixels` | `28×28×3600 = 2,822,400` | Max pixels for vision encoder. **Not supported with `llama-cpp-server`** — silently ignored, warning in logs |
| `prompt_label` | — | Custom prompt label |
| `layout_threshold` | `0.3` | Layout detection confidence threshold |
| `layout_shape_mode` | `"auto"` | Layout shape mode |
| `use_layout_detection` | inherits from constructor | Override per call |
| `format_block_content` | inherits from constructor | Override per call |
| `vlm_extra_args` | — | Extra arguments passed to the VLM |

## `save_to_markdown()` Parameters

| Parameter | Default | Description |
|---|---|---|
| `pretty` | `True` | Adds inline HTML styles. `False` = raw HTML without styles. See `output.md` |
| `show_formula_number` | `False` | Shows formula numbers |

## Standalone Layout Detection

`PaddleOCRVL` uses `PP-DocLayoutV3` (or V2) internally via the `PaddleOCR-VL-1.5` paddlex pipeline. You can use the same model **standalone** without launching llama-server or running VLM OCR:

```python
from paddlex import create_model

model = create_model(model_name="PP-DocLayoutV2")
# or PP-DocLayoutV3

for result in model.predict("page.png"):
    for box in result.json["res"]["boxes"]:
        print(box["label"], box["coordinate"], box["score"])
```

**Use case:** figure extraction from text-based PDFs. Render the PDF page to an image, run layout detection, and crop `image`/`chart` regions.

### Model name confusion — what works and what doesn't

| Model | Works standalone? | Used by `PaddleOCRVL`? | Notes |
|---|---|---|---|
| `PP-DocLayoutV2` | ✅ Yes | ✅ Yes (v1.5 pipeline) | Correct model |
| `PP-DocLayoutV3` | ✅ Yes | ✅ Yes (v1.5 pipeline, default) | Correct model |
| `PP-DocLayout-L` | ❌ No (oneDNN error) | ❌ No | Different model entirely |
| `RT-DETR-H_layout_17cls` | ❌ No (oneDNN error) | ❌ No | Used by `layout_parsing` pipeline only |

The `layout_parsing` pipeline (from `paddlex.create_pipeline(pipeline="layout_parsing")`) loads a **different** layout model (`RT-DETR-H_layout_17cls`) plus OCR, table, seal, and formula sub-pipelines. It is overkill if you only need bounding boxes.

## Our Configuration (project)

Defined in `src/config.py` and applied in `src/pipeline.py`:

```python
PaddleOCRVL(
    vl_rec_backend="llama-cpp-server",
    vl_rec_server_url="http://127.0.0.1:8080/v1",
    vl_rec_api_model_name="paddleocr",
)
# use_layout_detection=True (default)
# use_doc_preprocessor=False (YAML default)
```

llama-server launched with:
```
-m <model.gguf> --mmproj <mmproj.gguf>
-c 6144 -ngl 99 -b 512 -ub 512 -t 4 --prio 2 --temp 0.0 -kvo
```
