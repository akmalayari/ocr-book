# PaddleOCR-VL — Output Format and Post-processing

## Markdown Generation Flow

```
VLM generates raw content (HTML for tables, text for text blocks)
    └─► save_to_markdown(pretty=True)   ← our choice
          └─► _to_markdown(pretty=True)
                ├─ text/caption blocks  → format_centered_by_html()  → <div style="text-align: center;">...</div>
                ├─ table blocks         → format_table_center_func()  → inline styles on <td>, <th>, <table>
                └─ image/figure blocks  → format_image_scaled_by_html_func() → <img width="X%">
```

## `pretty=True` vs `pretty=False`

### `pretty=True` (default)

```html
<!-- Table caption -->
<div style="text-align: center;">Table 1: Table Title</div>

<!-- Table -->
<table border=1 style='margin: auto; word-wrap: break-word;'>
  <tr><td style='text-align: center; word-wrap: break-word;'>Col1</td></tr>
</table>

<!-- Figure -->
<div style="text-align: center;">
  <img src="imgs/img_xxx.jpg" alt="Image" width="31%" />
</div>
```

### `pretty=False`

```html
<!-- Table caption -->
Table 1: Table Title

<!-- Table -->
<table><tr><td>Col1</td></tr></table>

<!-- Figure -->
<img src="imgs/img_xxx.jpg" alt="Image" />
```

## Our Approach: `pretty=True` + Table Style Stripping

**Retained choice:** `save_to_markdown(pretty=True)` + regex in `postprocess.py` to remove inline styles from table tags only. `<div style="text-align: center;">` (captions, titles) and figure scaling (`width="X%"`) are kept.

```python
# In postprocess.py / clean_page()
text = re.sub(r"<table\b[^>]*\bstyle='[^']*'", "<table border=1", text)
text = re.sub(r"<(t[dh])\b[^>]*\bstyle='[^']*'>", r"<\1>", text)
```

Result:
```html
<table border=1>
  <tr><td>Col1</td><td>Col2</td></tr>
</table>
```

## What the VLM Actually Generates

The VLM generates block contents, not HTML wrappers:
- **Text blocks**: raw markdown text
- **Table blocks**: HTML `<table><tr><td>...</td></tr></table>` (without styles)
- **Figure blocks**: empty (the image path is handled by PaddleOCR, not the VLM)

Inline styles (`style='...'`) are added by PaddleOCR in post-processing within `_to_markdown()` — they are **not** generated by the VLM. Disabling them does not change generation speed.

## `format_block_content` vs `pretty`

These two parameters are independent and often confused:

| Parameter | Where | Effect |
|---|---|---|
| `format_block_content` | constructor / predict | Block formatting in `.json()` output. Default: `False`. |
| `pretty` | `save_to_markdown()` | HTML style addition in `.md` file. Default: `True`. |

`format_block_content=True` applies the same type of formatting but in the JSON representation of blocks (used for serving/API), not for the markdown file.

## HTML vs Pure Markdown Output

By default the pipeline converts HTML tags to pure Markdown (tables as pipe tables, figures as `![]()`, etc.). To keep the original HTML tags instead, use the CLI flag:

```bash
python main.py --keep-html
```

**What changes (default behaviour without `--keep-html`):**

| HTML | Pure Markdown |
|---|---|
| `<table>...</table>` | Markdown pipe table |
| `<img src="..." alt="..." />` | `![alt](...)` |
| `<div style="...">caption</div>` | plain text (unwrapped) |
| `<sup>er</sup>` | `^er^` |
| `<sub>2</sub>` | `~2~` |
| `<b>bold</b>` | `**bold**` |
| `<i>italic</i>` | `*italic*` |

**Notes:**
- Conversion runs **after** image path fixing, so relative paths are preserved.
- In Obsidian mode, wikilinks `![[...]]` are passed through untouched.
- A second pass of `clean_page()` runs after conversion to collapse any extra blank lines introduced by unwrapping `<div>` blocks.

## Figure Crops

PaddleOCR saves image region crops in an `imgs/` subfolder relative to the `save_path` passed to `save_to_markdown()`. The markdown references these crops by relative path.

In our pipeline: `save_path = output/figures/<page_stem>/` → crops in `output/figures/<page_stem>/imgs/`.
